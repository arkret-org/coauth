# Frontend Accessibility

This is the WCAG 2.1 AA smoke check for the Dioxus account SPA. The current
slice focused on login and verification-code flows because those are the
highest-friction keyboard and screen-reader paths.

## Implemented Checks

- Keyboard focus: `assets/main.css` defines visible `:focus-visible` outlines
  for links, buttons, inputs, selects, textareas, and tabindex targets. Form
  inputs and password visibility buttons keep a dedicated outline even where
  component-specific focus styles apply.
- Reduced motion: `prefers-reduced-motion: reduce` shortens transitions and
  animations and disables smooth scrolling.
- Login errors: `pages/login.rs` announces password-login failures through
  `role="alert"` and `aria-live="assertive"`, links the alert to both login
  fields with `aria-describedby`, and sets `aria-invalid` while an error is
  visible.
- Verification-code errors: `pages/email_verify.rs` and the registration email
  and phone verification steps announce OTP/code failures through assertive live
  regions. Successful resend messages use `role="status"` and
  `aria-live="polite"`.
- Label associations: login and verification-code inputs now have stable `id`
  values and matching `label for` attributes.

## Local Check

```powershell
rg -n 'focus-visible|prefers-reduced-motion|role: "alert"|"aria-live"|"aria-invalid"' crates/frontend
```

Run a keyboard pass on `/login`, `/register/{id}/verify-email`,
`/register/{id}/verify-phone`, and `/email-auth/{id}` when a backend fixture is
available. The expected behavior is visible focus on every control, immediate
screen-reader announcement for invalid credentials or code errors, and polite
announcement for resend success.
